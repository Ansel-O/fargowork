# FargoWork

FargoWork 是官方 **OpenYida CLI** 的公司流程附加技能包。把这句话交给能执行本机命令的 AI 客户端：

> 请从 https://github.com/Ansel-O/fargowork 安装或更新 FargoWork，按仓库说明准备官方 OpenYida CLI 并完成登录。

**前置需要安装官方 OpenYida CLI**，再安装本包；已有官方登录会话直接复用。安装及调用入口是 [SKILL.md](SKILL.md)。本版支持已核对的官方 CLI `2026.10.16` 和 `2026.10.19`，官方项目见 [openyida/openyida](https://github.com/openyida/openyida)。

装好后，直接说“帮我申请一张名片”。Agent 会补问必要业务信息，展示草稿，**停下来等你确认后再提交**。正常办理不展示隐藏字段或执行日志。

- 十四个正式流程：出差、采购、硬件申请、软件申请、对外费用、费用报销、出差费用报销、体检报销、默认银行卡变更、合同、用印、名片、挂牌、餐費與交通補貼。
- **Demo 独立分组**：保留年假、对外付款两个可发起的测试流程，仅在明确要求测试对应 demo 时进入，并在完整预览标明 Demo 测试。出差、采购两个 demo 已移除；原草稿不能继续或转换为正式申请。测试提交同样需预览后的新确认。
- **正式假期及销假均已迁移至 Moka，当前不可在本包发起。** 年假 demo 不替代正式申请；体检假也请转至 Moka 按当前规则办理。连同九项 HR，现有十六项迁移指引。
- 出差、采购、硬件、软件、付款、合同、名片、用印、费用报销、出差费用报销和餐費與交通補貼支持宜搭原生附件。采购最多 9 个、单件 20 MiB；硬件和软件最多 9 个、单件 100 MiB；用印按清单逐行绑定；餐费分别上传打卡证明与报销附件，每栏最多20件、单件100 MiB。[附件使用规则](references/ATTACHMENTS.md)
- 财务组目前支持正式对外费用、费用报销、出差费用报销、体检报销、餐費與交通補貼和默认银行卡变更。费用报销支持本人收款资料初填后修改、逐行不同原币换算，以及最多20件原生附件（单件100 MiB）。出差费用报销独立整理行程、关联出差、各项实报与餐补；餐补按支付币种建议，可保留明确手改，多币种拆行避免重复餐补。这两类报销先修改并确认明细，再补主表、确认完整申请后提交。正式对外费用、餐费交通也先确认各自明细，再补主表并确认完整申请：前者区分本次付款与合同总额，后者保留分钟时段、分别计算餐补和交通费，并按材料用途绑定打卡证明与报销附件。体检报销仅面向大陆员工本人，固定人民币，超过1500元自动封顶；五项收款资料同样从本人花名册初填可改，没有明细子表，完整申请预览后等新的提交确认。正式员工及每年一次沿原表提交校验。本次报销可直接补录或修改收款资料；成功后，仅在本次补录或修改且未说明是否长期使用时，询问一次是否另提默认银行卡变更，明确“仅本次”则不再问，不自动创建或提交第二单。也可主动单独申请变更，提交成功不代表默认资料已生效。
- HR 组的员工证明材料、推荐候选人奖励、试用期转正、试用期计划、雇主提供居所、入职、离职、转岗、HR 操作离职共九项已迁移，**不可在本包发起，请转至 HR 应用 Moka**。其中入职、离职、转岗和 HR 操作离职属于重要人事流程，不建议由 Agent 发起。
- Windows、Node.js 22 或以上及 npm；Mac 尚未验收。不另装一份 OpenYida，不注册 MCP，不连接另一套附件服务。
- 仅在问题确实影响办理时提示协助核查：组织资料找 HR，财务资料找 Finance，技术或不明确的问题找 IT。允许为空的隐藏字段保持无感。

流程目录按用途分为财务（finance）、假勤（leave）、资产（assets）、业务（business）和人事（hr）五类。人事流程及其迁移指引保留独立分类；每类的Skill、流程模块和配置分别放在 `skills/<类别>/`、`workflows/<类别>/` 和 `config/workflows/<类别>/`。正式、Demo测试及Moka迁移状态仍由配置区分，目录分类不会改变办理权限或固定目标。
