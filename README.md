## 1. 这是什么

FargoWork 是基于 [OpenYida](https://github.com/openyida/openyida) 的企业流程 Skill 包。你说清需求、提供材料，Agent 帮你整理申请，确认后发起宜搭审批。

它为 Fargo 在用流程提供统一入口：

| 分类 | 可以办理的事情 |
| --- | --- |
| 财务 | 费用、出差及体检报销，对外付款，餐费交通补贴，默认银行卡变更 |
| 资产 | 采购、硬件和软件申请 |
| 业务 | 出差、合同、用印、名片、挂牌 |
| 假勤 | 假期、销假等，引导前往 Moka 办理 |
| 人事 | 证明、推荐、试用期、入离职、转岗等，引导前往 Moka 办理 |

另保留年假、对外付款两个 **Demo**，仅供明确要求的测试。Demo 会向指定测试表提交真实流程，不能用于正式业务。完整范围见 [Skill 入口](SKILL.md)。

## 2. 怎么用

可以直接说：“这几张票据需要报销，先帮我整理明细。”

财务申请按这个顺序进行：

**确定公司和币种、必要项目归属 → 整理材料并计算明细 → 修改并确认明细 → 补主表 → 确认完整申请 → 提交。**

费用报销、出差报销、对外付款和餐费交通会自动打开各自的HTML明细，付款Demo也使用同样的保存方式。直接修改后点“保存”，告诉Agent“改好了”，它会回读并重算；也可以口述修改。无需选文件或导出，页面不可用时可编辑同一份MD。完整申请最后在对话确认。体检报销与银行卡变更直接对话，一次确认提交；体检仍只报人民币、上限1500元。餐费交通从打卡附件提取结束时间，开始默认18:00、听从用户明确说明，保留分钟精度和两类附件。

费用类别和科目会给出推荐及合适的备选，你可以接受，也可以修改指定行；固定科目按原规则执行。币种、汇率等资料只取公司维护的数据，不采用对话中的替代值或网络行情。体检报销等没有明细子表的流程直接确认完整申请。

个人报销的收款资料默认取花名册。你明确要求换卡时，才查本人已完成且同意的报销记录，或使用你本次提供的资料。对外付款使用本次外部收款方资料。最终申请经你确认后提交，后续仍由公司原审批流程审核。

## 3. 个性化、维护与企业适配

**记住习惯，不改公司规则。** 经你同意，Agent可以保存常见用途、语言和展示偏好；支持查看、修改、删除，升级保留。默认卡变更后，还会使用的旧卡可只记昵称、尾号和用途；以后明确换回时，从本人已完成且同意的历史报销查完整资料，查不到再提供。不存完整银行卡资料、凭据和原始单据。详见[个人偏好](references/PERSONAL.md)。

**资料复用，按需刷新。** 新申请先核对公司目录和必要资料；首版草稿起 24 小时内复用，修改不延长有效期。需要最新资料时，可以说“刷新公司资料”；期间的维护更新不会自动进入已有草稿。过期或首次无法核对时保留草稿，恢复核对后继续。新办理会检查更新，最多尝试两次，网络不通就跳过；推荐最新版与强制最低版本分别维护。详见[版本说明](references/WORKFLOW-DIRECTORY.md)。

**其他企业从结构入手。** `config/` 放公司和流程配置，`workflows/` 放办理逻辑，`skills/` 放交互说明，`shared/` 放共用工具；流程按财务、假勤、资产、业务、人事分目录。需要替换的文件及验证步骤见[企业适配指南](references/ADAPTING.md)。当前公共包未附目录页面模板和构建工具，接入另一家公司需要适配、验证后再交付。
