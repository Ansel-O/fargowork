# 体检报销

升级后建议新开会话；继续当前会话时重新加载新版入口和本流程说明。草稿按[24小时复用与刷新](../../../references/WORKFLOW-DIRECTORY.md#办理行为)：首个可核对草稿起24小时，编辑不续期、提交不全量重查；过期或用户要求用 `refresh <draftId>`，保留输入、材料和回执，展示并确认实际差异。

使用 `medical_checkup_reimbursement`，固定目标 `FORM-FEA10FAA67204CCABD64295DE2A91857DH4G`。本流程面向大陆员工，仅报销人民币，报销上限1500元。正式员工及一年一次由原表提交校验，不另查员工年度报销历史或增加本地资格判断。当前仅办理登录人本人申请。

沿用[公司维护源与个人选择](../../../references/FINANCE-DETAILS.md#公司维护源与个人选择)：人民币、封顶金额及公司目录按既定规则，不被口述、网络或 personal 覆盖。本表没有会计科目选择和换汇步骤，不新增这两项；员工本次金额及允许修改的收款资料仍按原规则核对。

从本文件向上三级确定完整包根。首次安装按[入口 Skill](../../../SKILL.md#首次安装)准备，以后复用官方 OpenYida 登录态，不注册 MCP。在包根执行：

```text
node scripts/fargowork.cjs status
node scripts/fargowork.cjs requirements medical_checkup_reimbursement
node scripts/fargowork.cjs prepare medical_checkup_reimbursement --input <绝对路径的UTF-8业务JSON>
```

由 Agent 整理输入，员工可以直接提供金额和医院发票，其他佐证可以一并附上。材料读取优先使用宿主已具备的 PDF、图片或 OCR 能力，仅处理本次提供的材料。同一笔体检费用的发票、订单、支付截图归为一组证据，只计一次；区分套餐标价、实付和本次实际申领金额，排除非本次体检费用，不把材料中所有数字相加。金额或归属确有冲突时集中核对，保留员工更正。没有费用明细子表，不套用其他报销流程的八列及两轮确认。

原表还提示应在体检当月提交。发现材料日期可能跨月时如实提醒，不增加本地日期门禁。

## 准备本次申请

先说明本流程固定人民币，并沿原合同公司默认和支付公司候选核对本次公司，不增加外币选择或强制补齐原可空公司。`prepare` 在金额尚未提供时也返回已核对的公司及 CNY，再补金额。**默认打开返回的 `detailEditor.path` 展示体检专用 HTML，不等待用户要求**，可附一句“体检申请金额／封顶后的报销金额／人民币”摘要。按[HTML 明细与修改](../../../references/FINANCE-DETAIL-EDITOR.md)办理；宿主不能内嵌时提供本地 HTML 链接供浏览器打开。仍只进行原有完整申请确认，不虚构费用子表。

业务输入 `amount` 为员工本次申请的人民币金额，可用数字或十进制字符串。保留原金额交给脚本计算，超过1500元自动调整为1500元；不要先改写输入使原金额和调整记录消失。按原表保留两位小数，不自行追加最低金额限制。币种固定 CNY，不传币种、汇率、人员、员工状态、申请年份或审批人等系统字段；外币材料不能擅自当成人民币，也不自动换汇。

按[原生附件指南](../../../references/ATTACHMENTS.md)，先由宿主将本次选定文件准备为可访问的本地文件，再将绝对路径字符串放入 `attachments`。原表附件必填，最多9件，每件100MiB，未限制文件类型。原表说明要求医院发票供审核；若员工仅提供体检报告等材料，提示补充医院发票，不把体检报告当作费用发票。不额外要求银行卡照片或员工身份证明。Agent 按本次明确纳入的材料选择最终附件，排除、重复或无关材料不自动上传；脚本核对最终附件清单、文件限制和上传状态，不代替材料语义审核，不能把文件名或文字描述当作已上传的附件。

与其他财务流程一致，先从本人花名册带入收款五项资料，无需员工重新填写。只有员工明确修改时才通过以下输入覆盖；账号始终是完整字符串，保留前导零及全部数字，不转为数值或猜测缺失内容：

| 资料 | 明确修改时的业务输入 | 默认来源 |
| --- | --- | --- |
| 收款账号 | `bank_account` | 本人花名册 |
| 开户银行 | `bank_name` | 本人花名册 |
| 开户城市 | `bank_city` | 本人花名册 |
| 开户支行 | `bank_branch` | 本人花名册 |
| 账户名称 | `account_name` | 本人花名册 |

支付公司首次按合同公司带入，可用 `payment_company` 修改或明确传空字符串。合法选项来自本表的“有银行账号＝是”支付公司目录，沿用脚本返回的选择，不能套用其他报销表的员工支付公司映射。支付公司币种若与人民币要求冲突，请 Finance 核对配置，不改成港币或其他币种继续。支付公司及原表其他可空字段不额外强制补齐。

后续继续 `prepare medical_checkup_reimbursement --input <文件> --draft <同一draftId>`。省略项保留当前草稿；空字符串表示明确清空收款资料或支付公司，不能再次被花名册覆盖。口述修改回写同一草稿并重新 `prepare`；手动修改由员工在 HTML 导出文件交 Agent 执行 `apply-edit`。两种方式都展示工具新返回的 HTML 和实际封顶结果；手动应用后取得对新版的新确认，导出或应用不代替确认。只集中补充脚本返回的实际缺项。合同公司、员工状态、申请年份和审批人均按原有来源填写，正常时无感；不要让员工确认隐藏字段。

员工明确要求本次换卡时，按[本次换收款卡](../../../references/PERSONAL.md#本次换收款卡)在同一草稿检索本人遮掩历史候选，或自行提供；选定后整组替换五项，再纳入最终申请确认。默认仍取花名册，不因 personal 偏好自动查卡。

## 预览和提交

执行 `node scripts/fargowork.cjs preview <draftId>`，打开本次 `detailEditor.path` 展示完整申请 HTML：申请人、日期、支付公司、人民币币种、原申请金额、实际报销金额、收款五项和全部报销附件。发生封顶时明确告知“原金额X元，按上限调整为1500元”，不能只显示原金额，也不能把封顶描述为审批通过。

**展示完整预览后停止，等待员工对此次申请的新提交确认。** 初始“帮我报销”或提供附件不代替确认。修改金额、收款信息或材料后，在同一草稿重新准备、预览并确认。

收到确认后执行 `node scripts/fargowork.cjs submit <draftId> --confirm <本次preview的draftSha256>` 一次，再执行 `node scripts/fargowork.cjs result <draftId>`。结果未知只核查原草稿，不新建重提。原表返回员工资格或年度次数校验失败时，按实际返回说明并停止，不伪造身份、状态、年份或重复提交绕过。成功报告编号和实际报销金额；提交成功不等于审批通过，未完整回读也不声称核对通过。

本次补录或修改收款资料时，先完成本申请。成功后，若员工尚未说明是否长期使用，可以简短询问一次是否另办[默认银行卡变更](../default-bank-change/SKILL.md)；已说“仅本次”则不再问。不自动创建或提交第二单，不直接修改花名册。排障按[DEBUG](../../../references/DEBUG.md)，不索取凭据。
