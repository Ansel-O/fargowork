# 办理中的资料检查

只有确实影响当前可办理流程时才使用本说明。正式假期及销假均已迁移至 Moka，直接告知前往 Moka，不收集资料或使用下表排查旧流程。正常流程不展示隐藏字段，不请员工核对后台主管、行政联系人、内部归属或编码；原规则允许为空且不影响办理时直接继续。

| 实际问题 | 处理 |
| --- | --- |
| 员工应提供的日期、事由、金额或文件缺失 | 合并询问对应业务信息，修改同一草稿。 |
| 本人默认收款资料尚未维护，或本次需要改卡 | 按员工明确的资料继续当前报销或餐补，保留最终申请确认，不重复确认已明确的本次修改。提交成功后，仅在本次补录或修改了收款资料、且员工未说明是否长期使用时，简短问一次是否另提[默认银行卡变更申请](../skills/finance/default-bank-change/SKILL.md)；已说“就这一次／仅本次”的不再问。该项可选，不提前打断报销、不自动创建或提交第二单、不改写花名册；仅员工主动要求先改默认资料时切换，并保留原草稿。变更申请需独立预览和新确认，提交不等于生效。 |
| 内容详情已明确，费用类别或会计科目尚未选择 | Agent 从合法完整配对中建议一组；合理备选在表外按行说明，供员工接受或明确替换。保留合法明确选择，不把整个目录转给员工；用途不足时只补问业务事实。详见[科目交互](FINANCE-DETAILS.md#科目推荐与独立备选)。 |
| 必需组织、主管、任职资料缺失或不唯一 | 简短说明需要 HR 核查，不能让员工手填主管ID或内部字段。 |
| 当前查询未匹配到支付公司或其他必需财务资料 | 保留材料、暂停提交，请维护者先核对读取权限、匹配条件和返回结果。仅说明暂时未能核对成功，不断言资料未维护，也不直接要求 Finance 新增记录。 |
| 必需业务归属、币种、科目、供应商等财务配置缺失或不唯一 | 请 Finance 核查，不能猜值或把系统维护转嫁成选编码。 |
| 员工提出的汇率、币种或科目不符合公司维护数据 | 按[公司维护源规则](FINANCE-DETAILS.md#公司维护源与个人选择)核对。合法科目可重新选择；汇率不能用口述、网络或个人记忆覆盖。员工仍有异议或来源不可用时保留草稿、暂停提交，请 Finance 核查；不改配置、切换流程或关闭校验继续。 |
| 登录、权限、接口、版本、格式故障或无法明确分类 | 请 IT 核查；不要反复登录或修改脚本绕过。 |

不能凭“字段像审批人”新增必填，也不能把HTTP失败当成正常可空。是否阻断以本流程已核对的业务规则和当前必填要求为准。成功返回空目录与明确拒绝访问是不同的问题；空结果也可能与读取范围或匹配条件有关，只有核实缺失后才请相应维护方补录。员工说明只讲业务问题和下一步，不展示内部命令、编码和查询链；保留材料不等于草稿已经保存。

问题按实际原因分工：公司规则由维护者更新，财务目录与汇率由 Finance 维护，员工确认本次事实与合法选择，财务按原流程审核；工具或权限故障由 IT／包维护者排查。不要把一次 Agent 推荐或用户接受描述为财务已审核，也不把所有问题笼统归给员工。联系人使用公司现有支持渠道。

可空隐藏字段不加额外确认。最终申请只确认一次业务预览；费用报销此前另有明细整理确认，不能代替最终提交确认。操作不成功与内容回读暂未核验分开，任何结果未知都不自动重试写操作。详细支持信息见 [DEBUG](DEBUG.md)。
