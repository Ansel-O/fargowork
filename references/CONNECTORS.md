# 连接器与资料来源

员工先安装官方 OpenYida CLI，再使用 FargoWork 附加技能包。本包复用官方 CLI 的当前登录态和账号，通过宜搭访问现有连接器及固定资料表；不内置另一份 OpenYida，也不建立独立的 FargoWork 登录会话。员工无需填写连接器账号、AppSecret 或 token。缺少权限时停止办理，由管理员检查现有配置。

官方 CLI 来源为 [openyida/openyida](https://github.com/openyida/openyida)。本版已核验 `2026.7.14-2` 和 `2026.10.16` 的身份接入合同，安装器会检查版本；这不等于四流程已在两个版本、所有账号下完成真人验收。安装时只保存非秘密的官方工作目录关联，后续调用自动复用；官方 CLI 切换账号后，本包也会使用切换后的身份，旧账号草稿不能继续提交。存在多个官方账号配置且未选定时，需要本人选择，包不会自动猜选。

| 能力 | 固定调用 | 用途与限制 |
| --- | --- | --- |
| 本人花名册 | `Http_5c72b42d47f14a1983767932f6c1d4f1` / `getUserMessage`，连接 `15597` | 查询办理所需的本人身份、任职部门、办公地点、合同公司、员工状态或假勤组；每个流程声明必要字段。 |
| 部门详情 | `Http_75b8f8aef03c4b40815462052ba21a13` / `operation-1`，连接 `15624` | 核验本人任职部门或已选项目对应部门，并取来源顺序中的第一位主管。 |
| 宜搭资料表 | 包内工作流声明的固定只读表 | 查询下表所列业务资料，不能发起这些资料表对应的流程。 |
| 原生附件 | 宜搭上传签名、OSS 上传、附件登记 | 仅出差、采购、付款的原生附件组件；同一次 OpenYida 身份，附件随确认草稿提交。 |

这里的连接编号是宜搭已保存的连接引用，不是凭据，也不表示员工自动获得了管理员权限。能否调用由平台权限决定，下游可读取的范围还取决于预配置应用账号。

## 四流程实际需要的只读资料

| 流程 | 资料范围 |
| --- | --- |
| 年假 | 本人花名册；本人指定年度的年假余额；本人假勤组在请假日期范围内的日历调整；本人办公室行政、签约公司的考勤管理员。 |
| 出差 | 本人花名册及办公室行政；生效项目目录、所选项目的部门映射、该部门详情和主管。 |
| 采购 | 本人花名册及办公室行政、IT 联系人；公司币种目录、所选币种兑港币汇率。 |
| 对外付款 | 本人花名册及任职部门；付款公司、币种、财务和出纳配置；供应商、银行资料、费用科目、部门业务层级；所选项目的有效关系、汇率；用户需要时只读查询本人可关联的合同或用印记录。 |

查询基础资料不等于开放通用检索。包内脚本固定表单、查询用途和字段，不提供任意 `formUuid`、`userid`、API 地址或连接器参数入口。数据源和连接器发生变化时，应更新并核验对应模块，不能让 Agent 临时猜接口、切换表单或绕开检查。

JS 模块继承已核对的网页规则，直接计算和拼装必要字段；不会执行从网页获取的任意代码。年假保留余额、工作日、半天及调休规则；出差和付款保留部门、项目及主管关系；金额、管理员和其他隐藏业务字段由模块补齐。字段或选项不符时停止办理。

## 当前权限边界

已有验证表明，某已登录账号可通过现有花名册连接器指定其他 `userid` 读取姓名；当前包仅传本人身份并核验返回结果，**没有修复连接器本身的跨人查询风险**。该事实不代表已验证所有员工、所有字段均可读取。

本地 Skill 和 JS 都可被用户修改，不能作为公司数据的授权边界。宜搭及连接器的实际权限仍由管理员在平台侧控制。不要将“插件限制只查本人”描述成“平台已保证只能查本人”。

这条路线直接使用 OpenYida 和宜搭权限，不经过 FargoWork Server；原 Server 的 `MCP_allow` 角色门禁也不会在这里执行。
