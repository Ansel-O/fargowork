# 连接器与资料来源

员工先安装官方 OpenYida CLI，再使用 FargoWork 附加技能包。本包复用官方 CLI 的当前登录态和账号，通过宜搭访问现有连接器及固定资料表；不内置另一份 OpenYida，也不建立独立的 FargoWork 登录会话。员工无需填写连接器账号、AppSecret 或 token。缺少权限时停止办理，由管理员检查现有配置。

官方 CLI 来源为 [openyida/openyida](https://github.com/openyida/openyida)。本版适配 `2026.10.16`、`2026.10.19`，安装器检查版本。登录、账号配置、续期、Schema、资料查询、流程提交和回读使用官方能力；本包不再保存官方工作目录关联或补丁登录程序。官方切换账号后，本包也会使用切换后的身份，原账号草稿不能继续提交。多个账号配置未选定时由本人选择，包不会自动猜选。

页面现有连接器动作和原生附件仍保留少量接口适配，调用官方 token provider 获取当前身份，不读取凭据文件。该 provider 不是独立的公开 SDK，所以本版固定已验证版本，不宣称兼容全部后续版本。附件操作方法见[原生附件说明](ATTACHMENTS.md)。

| 能力 | 固定调用 | 用途与限制 |
| --- | --- | --- |
| 花名册用连接器 | `Http_5c72b42d47f14a1983767932f6c1d4f1` / `getUserMessage`，连接 `15597` | 每个流程只查其配置声明的字段，默认仅本人；挂牌选人、出差报销授权代办和硬件、软件固定 IT 主管姓名用途见下文。 |
| 部门详情 | `Http_75b8f8aef03c4b40815462052ba21a13` / `operation-1`，连接 `15624` | 核验本人任职部门、已选项目对应部门，或硬件、软件配置的固定 IT 部门；主管选择按流程配置执行并保留来源顺序。 |
| 部门链 | `Http_75040e999ce6470cae848835cbb17024` / `GetParentId`，连接 `19159` | 共用工具保留完整部门链；挂牌从所选人员的部门查链，再按该流程配置取根部门下面一级。员工不填写部门 ID。 |
| 宜搭资料表 | 包内工作流声明的固定只读表 | 查询下表所列业务资料，不能发起这些资料表对应的流程。 |
| 原生附件 | 宜搭上传签名、OSS 上传、附件登记 | 只支持当前可办理流程声明的附件字段；用印按清单行绑定，餐费打卡证明与报销附件分别绑定；所有假期、销假及已迁移 HR 流程不上传。 |

这里的连接编号是宜搭已保存的连接引用，不是凭据，也不表示员工自动获得了管理员权限。能否调用由平台权限决定，下游可读取的范围还取决于预配置应用账号。

查询基础资料不等于开放通用检索。包内脚本固定表单、查询用途和字段，不提供任意 `formUuid`、`userid`、API 地址或连接器参数入口。数据源和连接器发生变化时，应更新并核验对应模块，不能让 Agent 临时猜接口、切换表单或绕开检查。

首个可核对草稿起24小时复用已取得的合法查询结果；编辑不续期，提交不全量重查。新选择缺来源时只补取对应资料；用户要求或过期时用 `refresh <draftId>`，重取后展示差异。复用不扩大查询对象或字段，登录身份及平台权限仍按原规则处理。

四正式个人报销仅在本人明确换收款卡时，按[本次换卡](PERSONAL.md#本次换收款卡)读取固定四来源的本人、完成且同意记录，先核对户名再返回遮掩候选；不查询代办对象的历史，不混入外部付款或Demo。普通报销不自动查历史，体检也不以此检查年度资格。

正式假期和销假已迁移至 Moka，当前不查询花名册、余额、日历、病假历史或原请假单。保留的正式假期规则和字段约束不是开放调用入口，体检假也转至 Moka。只有明确测试年假 demo 时，才按该 demo 的固定配置查询本人必要资料、余额和日历，不扩大到正式假期。

JS 模块继承已核对的网页规则，直接计算和拼装必要字段；不会执行从网页获取的任意代码。出差和付款保留部门、项目及主管关系；金额、管理员和其他隐藏业务字段由模块补齐。字段或选项不符时停止办理。

## 查询对象与字段规则

**花名册默认只查当前登录人。** 登录身份直接取自官方 OpenYida，不接受员工或 Agent 指定任意 userid、字段清单或替换身份参数。本人查询结果必须匹配登录人；下列限定用途的结果必须匹配脚本确定的人员。响应包含公司标识时也须匹配登录公司，整个处理过程始终绑定当前登录公司，否则停止办理。

挂牌先用官方员工目录按姓名选择人员，再自动填写其必要花名册资料。姓名不唯一时先选人，不逐个查询候选人的花名册。此例外只用于挂牌，不能用于批量导出、其他流程或其他资料查询；草稿归属、实际提交者和发起部门仍绑定登录人。

出差费用报销另有受限代办规则：只有本流程配置获准的登录人员，才可通过官方员工目录明确选择其他报销人。后续本人资料、支付公司和关联出差均绑定本次报销人；草稿归属及实际提交者仍是登录人。选人不授予其他流程的查询权限，不读取全量人员资料，也不自动为对方发起默认银行卡变更。

硬件和软件申请使用流程配置中的固定 IT 部门，部门详情返回的主管列表按来源顺序取第一位，仅查询其 `sys00-name` 以填写 IT 主管。查询对象由这次部门结果派生，员工和 Agent 不能另传人员、部门或花名册字段。这一用途不能用于挂牌之外的任意选人，也不能扩展到其他流程；实际发起人仍是登录人。

HR 目录的九项及正式假期、销假均已迁移至 HR 应用 Moka，入口只提供迁移提示，不读取人员资料、上传或发起旧流程。年假Demo仅按上文明确测试范围办理。餐費與交通補貼在财务组继续办理。保留的业务模块和字段配置不会开放调用；其中入职、离职、转岗及 HR 操作离职不建议通过 Agent 发起。

各流程只读取办理所需字段，不查询全量花名册，也不在失败后扩大范围。缺失值按原流程的必需或可空规则处理；只有影响办理时才提示核查。

固定流程所需的部门、项目和公司资料仅限对应业务的固定用途；不能用花名册连接器进行人员搜索、批量查询或其他未声明的数据查询。上述范围不因测试、排障或临时需求而放宽。

所有操作仍须满足宜搭及公司的权限要求。无法读取所需资料时联系管理员处理，不尝试其他入口。员工无需提供连接器凭据或修改平台配置。

## 花名册调用合同

办理流程时使用包内业务命令，由共用工具按下表生成连接器请求。Agent 不自行拼接任意人员或字段查询，也不修改配置来扩大本次办理范围。

| 参数 | 格式 | 取值约束 |
| --- | --- | --- |
| `Content-Type` | 字符串 `application/json` | 固定值 |
| `Query.agentid` | 包内公司配置的应用 AgentId | 使用 `config/company.json` 的 `rosterAgentId`，不是员工 ID |
| `Query.userid_list` | 字符串 | 本包每次仅一个确定人员；默认取登录人，挂牌取已选定人员，出差报销取本次授权选定的报销人，硬件和软件主管姓名查询取固定部门派生的第一位主管；不传数组或多人列表 |
| `Query.field_filter_list` | 字段编码组成的逗号分隔字符串 | 必须是当前流程允许名单的非空子集；不接受空项、重复项、通配符或未声明字段 |

每个流程本人查询的准确字段编码以自身 `config/workflows/<类别>/<流程>.json` 中的 `policy.rosterFields` 为准；正式出差独立声明下表五项字段。出差报销代办范围由本流程 `policy.delegation` 声明，所选报销人仍只读本流程必要字段。挂牌的所选人员范围单独由 `policy.selectedEmployeeRosterFields` 声明；硬件、软件的固定部门及主管姓名范围由 `policy.departmentRoles` 声明，不从其他流程合并字段。

连接器响应解包后，`result` 必须只有一个员工，`userid` 必须与本次查询对象相符；返回中带企业标识时，也须匹配当前登录企业。存在非零业务错误码、错人、错公司或冲突字段时停止办理。

工具向流程模块统一提供以下结构。这里是格式示例，实际字段以当前流程配置和查询结果为准：

```json
{
  "userid": "CURRENT_EMPLOYEE",
  "corp_id": "CURRENT_CORP",
  "field_data_list": [
    {
      "field_code": "sys00-name",
      "field_value_list": [{"value": "姓名示例", "label": "显示名称示例"}]
    }
  ]
}
```

规范化输出的 `corp_id` 取自当前登录上下文，不要求连接器必返此字段。工具只保留本次请求的字段，以及值中的 `value`、`label` 和存在时的 `item_index`。`field_value_list` 可以有多项；编码、显示名称和明细序号各有用途，不把它们混用或任取第一项。缺失字段与空值按该流程已有规则处理，不扩大查询来补齐。
