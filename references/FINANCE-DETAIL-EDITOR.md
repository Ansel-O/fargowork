# 财务明细预览与手动修改

财务申请先确定支付公司及收款／付款币种，再整理明细。涉及项目的流程还要明确项目归属。用户已经说清的内容直接沿用；只有一个合法公司／币种组合时直接展示采用，多种组合才需要选择。

可以在对话中修改，也可以打开本地 HTML 手动修改。两种方式都回到同一份草稿，交原工作流校验、重算。单笔申请可以用一句话展示金额、币种及必要信息，不必制造一张费用子表。

## 打开和应用修改

Agent 在已有草稿上运行：

```text
node scripts/fargowork.cjs editor <draftId> [--output <HTML绝对路径>]
```

打开返回的 HTML 文件。用户可以修改字段、增加或复制明细、删除、调整顺序，以及更改材料归属。页面沿各流程原字段显示，汇率、固定科目和计算结果只读。公司、币种、项目、科目、关联出差等从工具已经核验的候选中选择；候选不全时让 Agent 刷新。

用户点“导出修改文件”，将下载的文件交回 Agent，然后运行：

```text
node scripts/fargowork.cjs apply-edit <draftId> --input <修改文件绝对路径>
```

命令重新核验业务输入并更新草稿。Agent 展示实际计算结果及待补项；需要继续修改时重新生成 HTML。导出文件本身不代表草稿已经保存，也不代表明细确认或申请提交。

自然语言修改之后，旧页面会因草稿已更新而拒绝覆盖。请打开新版页面再改，不要将旧页面套到新草稿。修改项目归属时会清除旧项目的依赖分类，重新核对项目、部门及科目，费用金额和真实日期保留。

## 七个入口各自保留的内容

| 入口 | 预览与编辑 |
| --- | --- |
| 费用报销 | 原八列、项目归属、每行合法类别与科目、材料关系 |
| 出差费用报销 | 真实行程日期、逐行关联出差、飞机／车船、住宿、交通、其他费用、餐补及备注；餐补建议天数独立显示 |
| 正式对外付款 | 本次付款金额及统一币种、合法类别／科目，主表阶段再补收款资料及关联业务 |
| 餐费交通补贴 | 分钟级起止时间、加班事由、交通费；公式餐补只读，打卡证明与报销附件用途分开 |
| 体检报销 | 单笔原申请金额、人民币封顶结果及原收款资料，没有虚构费用子表 |
| 默认银行卡变更 | 原资料对照和新五项资料，账号始终作为字符串 |
| 对外付款 Demo | 明确标注 Demo，按独立测试流程字段展示 |

四个有明细阶段的正式财务流程继续采用“确认明细 → 补主表 → 确认完整申请 → 提交”。体检、默认银行卡变更及 Demo 保留自身的完整申请确认步骤。首轮明细页面不会提前展示需要到主表阶段才补的银行资料。

复制一条明细后应调整金额和日期，避免把同一笔费用重复计算。删除明细时，失去对应行的材料会变为待确认；不纳入的材料须写明原因。增加新附件仍交由 Agent 处理，页面不允许直接改写原文件路径。

## 适配说明

此 HTML 的样式和脚本全部内嵌，可离线打开；没有登录、网络请求或业务提交接口。宿主没有可靠回传能力时统一使用修改文件，不声称网页能自动保存到 Agent。不能显示 HTML 的客户端可以继续使用文字预览和自然语言修改。

`shared/finance-detail-editor.cjs` 提供：

- `createEditor({workflow,draftId,input,review,prepared,materials,stage,choices,rowIds,previousDocument})`：生成 `document`、`html`、`rowIds` 和 `baseRevision`。`stage` 为 `details` 或 `application`。
- `revision({workflow,draftId,input,review,prepared,materials})`：生成当前内容摘要；命令入口也可传入自己的 `revision`，但导入时必须采用同一口径重新核对。
- `collectChoices(...results)`：收集 `editorChoices`、待补字段候选及既有科目合法配对。
- `applyEdit({document,edit,currentRevision,input,materials})`：拒绝错误草稿、旧修订、非法字段或候选，返回合并后的语义 `input`、`materials`、`rowIds`。调用方随后执行原工作流，再持久化与展示结果。

候选以语义字段为键，例如 `payment_company`、`items[*].original_currency` 或 `items[0].trip_instance_id`；值为字符串数组或 `{value,label}` 数组。关联项只显示名称，真实关联 ID 仍由工具持有。新增行可以使用已提供的候选，仍须由工作流复核当前身份、审批状态及分类配对。

修改文件绑定流程、草稿及基础修订，材料用稳定行标识关联，导入时再转换为当前行序。展示标识不进入宜搭业务字段。缺省值、清空和数字 0 分别保留；仅展示的默认值不会因导出而变成手工覆盖。

模板和修改文件包含本次申请资料，应保存在本地草稿目录，不加入公共仓库或作为个人长期记忆。产品模板及测试只使用合成数据。
