# 财务明细编辑与回读

先按本流程规则确定公司和收款／付款币种，涉及项目时明确项目归属；银行卡资料变更不涉及币种，不增加这一步。需要选择的合法组合唯一则采用并告知，多个才询问；**体检固定CNY，支付公司保留原合同公司默认及可空规则，不因目录唯一强填，不套员工支付公司映射**。草稿首个可核对版本起24小时复用合法资料，编辑不续期；新缺项才定向补取，过期或用户要求用 `refresh <draftId>`。按既定编排办理，不因普通修改全量重查。

## 本轮格式路由

| 入口 | 默认载体与结构 |
| --- | --- |
| 费用报销 | MD：“七列明细＋按类别分组的少量科目候选”；项目分支保留项目字段 |
| 出差费用报销 | MD：每条明细独立一块，日期、关联出差、费用和差旅津贴放在一起 |
| 正式对外付款 | MD：“五列付款明细＋按类别分组的少量科目候选”；统一主表币种，项目保留原分配字段 |
| 餐费交通补贴 | MD：分钟级开始／结束时间、加班事由、公式餐费补贴、交通费、备注；两类材料分用途保留 |
| 体检报销 | MD：可改原申请金额、固定CNY、实际封顶金额和支付公司；完整申请保留收款五项及附件名，一次完整确认 |
| 默认银行卡变更 | 直接在对话核对原、新资料及变化，不生成HTML或MD，一次完整确认 |
| 对外付款 Demo | 暂保留HTML及原有编辑方式，后续单独处理 |

费用报销、出差报销、正式对外付款、餐费交通补贴和体检报销均默认 MD；这五个入口不再提供 HTML 或要求手改导出。对外付款 Demo 保留 HTML，不与正式付款混用。工具 `review`、`prepare`、`preview` 及修改命令按流程返回 `detailEditor.path`，Agent 用文件编辑器打开或给可点击本地文件链接。每轮展示同一草稿最新内容并简短回显变化。体检直接 `prepare`，不增加 `review`／`confirm-details`；工具 `nextAction` 决定后续步骤，文件展示不改变确认次数。

## 五份 MD 固定模板

费用、出差和正式付款明细前醒目显示（正式付款用“付款金额”）；餐费交通采用下述短提示：

> **只需修改明细，无需自己计算总额。保存后告诉 Agent“改好了”，报销金额和总额会重新计算。**

**费用报销：** 表头标明公司、报销币种及项目归属；七列为费用类别、会计科目、内容详情、原币金额、原币种、报销金额、备注。类别和科目保留公司目录的编号、中英文、标点等完整原文。原币金额可直接修改；科目候选在明细后按类别分组、去重，便于复制替换，不附逐行长篇理由或评分。各原币分别小计，报销金额按报销币种合计；不混币相加。

**正式对外付款：** 表头标明支付公司、统一主表付款币种 `currency` 和项目归属；五列为费用类别、会计科目、付款内容、本次付款金额、备注。金额只填本次付款，不把合同总额或历史已付相加。类别／科目保留完整原文，候选同费用报销按类别分组、去重；项目仍保留逐行项目部门与业务层级，不把共用项目类别改为各行独立类别。不增加逐行原币种、汇率或后台港币计算列。

可选科目流程由Agent从 `recommendationContexts` 的合法配对中结合用途给出推荐，筛少量合理备选；模板不替代判断、不展示全目录、不编置信百分比。体检没有科目选择。可在适用流程 `review`／`prepare` 的顶层输入传展示元数据：

```json
{"recommendations":[{"category":"公司目录的完整类别原文","account":"公司目录的完整科目原文"}]}
```

省略沿用，`[]` 清空；工具只纳入合法配对，与当前已填科目合并按类别去重。这些元数据不进入业务输入或提交字段。员工已有合法明确选择保持；普通出差和餐费交通的固定科目不开放改选，餐费交通不增加科目候选。

**出差费用报销：** 每条独立块完整保留出发地、目的地、地区、起止完整日期、关联出差、四项实报费用、原币种、报销金额、差旅津贴币种／每日标准／建议天数／金额／分配说明、适用项目字段和备注。可以换行，不把同一条的行程、费用和津贴拆到不同表。原表“飞机、车船票款”包含火车票，退票费放“其他费用”和备注，不自造列。真实行程天数与津贴建议天数区分；首尾均计，按行程顺序仅自动建议前行未覆盖的日期，重叠归前段。

**餐费交通补贴：** 明细仅显示公司／币种、六个业务字段及普通序号、各自合计和短提示“只需修改明细，保存后告诉Agent‘改好了’，金额和总额会由代码重算”。六字段为开始时间、结束时间、加班事由、餐费补贴、交通费、备注。时间到分钟，默认加班当天18:30；日期不明先问，明确时间／清空保留，不猜前一天或用申请日替代。餐补按报销币种原公式只读、交通费可改，无项目及科目选择。打卡截图和报销票据分别入两附件栏，不默认合并；完整申请补真实主表及两栏文件名。材料台账、内部ID、用途与转换映射后台保持，不生成员工材料表或来源说明。

**体检报销：** 单笔MD只显示支付公司、可改原申请金额、固定CNY和实际报销金额，超过1500元由原代码封顶并保留原申请额。完整申请补真实主表、花名册默认或明确修改的收款五项及附件名。不造费用子表、材料台账、项目、科目或汇率；公司按原合同默认和“有银行账号”目录，原可空字段保持可空。正式员工及一年一次由原表校验，本地不加资格判断；仍只有一次完整申请确认。

五份均不展示汇率；MD 内新增或手改汇率、派生报销金额、公式餐费补贴、后台港币金额、建议天数和总额不作为输入。使用已有公司来源及共享代码重算回写，体检无需汇率。员工明确修改的出差津贴含0和清空仍保留；未改自动建议不因回读变成人工覆盖。出差津贴、公式餐补及体检封顶结果各按原流程处理，不能互套修改规则。

## 口述修改与保存后回读

**口述修改：** Agent 将指定变化回写同一草稿，明细阶段用 `review ... --draft <draftId>`，主表阶段按原流程用 `prepare ... --draft <draftId>`。显式 `items` 替换整表，不能把单行当完整表传入；保留其他输入和材料范围。用共享代码重算，再展示更新后的同一 MD，仅回显受影响行和合计。

**手动修改：** 用户编辑原 MD 并保存，告诉 Agent“改好了”。Agent 直接回读原文件：

```text
node scripts/fargowork.cjs read-edit <draftId>
```

显式指定另一份已保存 MD 时，才使用：

```text
node scripts/fargowork.cjs apply-edit <draftId> --input <MD绝对路径>
```

不要求导出、上传、截图或搜索下载目录。先读后算，不先重新生成文件覆盖用户修改；成功应用并重算后才说草稿已更新。若不能访问原文件，明确说明需要能读取的文件位置，不假称已获得修改。普通金额修改不做整页截图检查。

文件绑定当前草稿及修订，稳定行标识用于材料归属、增删及重排，不进入宜搭业务字段。保留原材料纳入／排除范围和理由；删行后失去归属的材料须核对，不能悄悄丢弃。材料文件路径不作为普通明细字段开放修改。省略、清空和0分别保留；遇旧修订或无法判断行对应时只澄清冲突，不能猜测覆盖。

改项目时按原规则处理依赖分类，保留真实费用与日期；新候选缺来源才补取。主动刷新保留输入、材料和已知上传回执，展示实际差异并确认。有独立明细确认的流程首轮不提前补银行等无关资料；体检直接准备完整申请。费用／出差／餐费交通／体检默认收款来自花名册；正式付款使用本次外部收款方合同公司、开户行及字符串账号，仅明确需要才查本人历史付款参考，不套本人花名册收款。正式付款关联规则保持，不隐藏正常业务字段。

## 两次人工确认

费用、出差、正式对外付款和餐费交通补贴均用 MD，继续“展示明细 → 修改并确认明细 → 补主表 → 展示完整申请 → 确认提交”。

第一次用当前 `reviewSha256` 执行 `confirm-details`；补主表后执行 `preview` 并展示完整申请，停止并等待新的提交确认，再用本次 `draftSha256` 提交一次。编辑、保存、回读、导出、应用及摘要本身均不能代替确认。明细变更按原规则确认，未变部分不重问；主表银行等无关变化保留首轮确认。体检、默认银行卡和 Demo 保留自身一次完整申请确认，不新增轮次。

## 银行卡变更直接对话核对

默认银行卡变更不生成文件，不调用 `editor`、`apply-edit` 或 `read-edit`。员工提供文字或自愿给照片时，提取账号、户名、银行、城市和支行，前台可把城市／支行合为一组显示；不漏掉原生五项，不猜照片缺失内容。照片不上传到无附件的原表。

`prepare` 后在对话回显资料，修改用同一草稿的 `prepare` 保留其他项；`preview` 后完整核对旧新资料及变化，只等一次新的提交确认。24小时来源复用、明确清空、完整账号字符串和原表可空字段保持。旧编辑文件不能再导入，但不删除既有业务草稿。

变更申请提交后，仍会使用的旧卡才在本人明确同意后记为personal昵称、尾号、用途；不用就不记。以后明确换回时再从本人已完成且同意的历史报销核对完整资料，查不到请本人提供，见[PERSONAL](PERSONAL.md)。

## 尚未迁移的 HTML 入口

仅对外付款Demo保留HTML、独立供应商字段和原有导出应用方式。首轮 `prepare`、最终 `preview` 自动返回HTML `detailEditor.path`；宿主支持时打开，否则给本地链接。手动修改导出后通过 `apply-edit <draftId> --input <修改文件绝对路径>` 写回同一草稿，展示新版再按原步骤确认。页面没有直接提交接口，不声称浏览器输入会自动保存到Agent。其他五个财务文件编辑入口输出MD，银行卡变更直接对话核对。

文件编辑能力由 `supports` 判断；银行卡变更仍保留财务业务定义，不支持文件编辑。共用 `createEditor`／`revision`／`collectChoices`／`applyEdit` 继续供五份MD及付款Demo使用，绑定草稿和修订，候选及真实关联ID由工具持有。

本地明细和完整申请包含申请资料，应保存在本地草稿目录，不加入公开仓库或长期 personal 记忆；产品模板及测试只用合成数据。
