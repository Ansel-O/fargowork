# 财务明细编辑与回读

先按本流程确定公司和收款／付款币种，涉及项目时明确项目归属。合法组合唯一直接采用，多个才询问；体检固定CNY，保留原合同公司默认及可空规则；银行卡变更不增加币种步骤。首个可核对草稿起24小时复用公司资料，普通修改不全量联网复查；缺新项才补取，过期或主动要求时 `refresh`。

## 默认 HTML，同一草稿保留 MD

费用报销、出差费用报销、正式对外付款、餐费交通补贴、体检报销和对外付款Demo默认提供本机HTML。银行卡变更直接对话，不生成文件。

`review`、`prepare`、`preview`、`editor` 和修改命令自动准备页面：优先打开返回的 **`detailEditor.url`**，由侧边栏或浏览器显示，不能把后台MD路径误当HTML。FargoWork自动启动和复用随包Node保存程序，员工无需选文件、运行终端或导出。只在本机当前草稿范围保存，不提交宜搭。

若工具返回MD兜底，或宿主不能访问本机页面，打开 `detailEditor.path` 对应的原MD，用文件编辑器保存；不得假称HTML已打开或保存成功。用户主动偏好MD时用 `editor <draftId> --format md`；需要HTML再用 `editor <draftId> --format html`。已有草稿与确认规则不因展示方式改变。

## 三种答复与同一份数据

1. **“没有问题”且没有修改：** 沿本流程当前确认步骤继续，不重解析材料、重生成草稿或重查公司资料。
2. **在HTML改好并保存，或保存了原MD：** 员工说“改好了”或确认修改后，先 `read-edit <draftId>` 回读当前原文件，复用公司资料、共享代码重算，再展示受影响行和新合计并按原规则确认。HTML保存成功只代表本机文件已保存，不能跳过回读应用或视为提交许可。
3. **口述修改：** Agent更新同一草稿的语义输入，明细阶段 `review ... --draft <draftId>`，主表阶段 `prepare ... --draft <draftId>`；展示新页面。若工具提示已有未应用文件修改，先回读，不能生成文件覆盖员工保存的内容。

保存按钮与页面收到的Ctrl+S使用同一路径；若宿主截获快捷键，使用页面“保存”。关闭窗口不等于保存，不承诺自动保存。页面显示失败或修订冲突时保留输入，明确尚未保存，核对当前草稿；不猜测覆盖。成功后不需要导出、上传、截图或搜索下载目录。普通修改不做整页截图检查。

```text
node scripts/fargowork.cjs read-edit <draftId>
node scripts/fargowork.cjs editor <draftId> --format md
```

显式提供另一份已保存MD时才用 `apply-edit <draftId> --input <MD绝对路径>`。文件绑定草稿和修订；稳定行身份用于材料归属与重排，不进入业务字段。省略、清空和0分别保留。显式 `items` 替换整表，不能只传一行；删行后材料无归属须核对，不静默丢弃。

## 五份 MD 固定模板

HTML与MD保留各流程同一套业务字段。以下MD结构同时作为兼容入口，HTML改善排版而不改业务含义。

| 入口 | 明细结构 |
| --- | --- |
| 费用报销 | 类别、科目、内容、原币金额、原币种、报销金额、备注；项目保留原字段 |
| 出差费用报销 | 每条独立成块，同行程的日期、关联出差、四项费用和差旅津贴放在一起 |
| 正式对外付款 | 类别、科目、付款内容、本次付款金额、备注；统一主表币种，项目保留逐行分配 |
| 餐费交通补贴 | 开始时间、结束时间、加班事由、公式餐费补贴、交通费、备注；普通序号辅助对应 |
| 体检报销 | 单笔原申请金额可改、固定CNY、实际封顶金额及支付公司；无费用子表 |

醒目提示：**只需修改明细，无需自己计算总额。保存后告诉Agent“改好了”，金额和总额由代码重算。**

类别和科目保留公司目录完整原文。Agent结合用途给每行一组推荐，少量合理备选按类别分组去重；不编置信百分比、不罗列整个目录、不混入实际字段。HTML从合法候选中选择，MD可复制替换。已有合法明确选择保持，固定科目不开放更换。展示元数据：

```json
{"recommendations":[{"category":"公司目录完整类别原文","account":"公司目录完整科目原文"}]}
```

省略沿用，`[]`清空；工具校验合法配对，推荐元数据不提交宜搭。餐费交通、体检不新增科目。

五份模板不展示汇率。手改汇率、派生金额、合计、建议天数、公式餐补或后台港币金额不作为输入，后台用已有公司资料重算。各原币分别小计，报销总额按收款币种计算，不混币相加。

**出差：** 每块包含出发地、目的地、地区、完整起止日期、本行关联出差、四项实报费用、原币种、报销金额、差旅津贴币种／标准／建议天数／金额及备注。原表“飞机、车船票款”包含火车票；退票费放其他费用及备注，不造列。津贴按行程顺序只自动计前行未覆盖的日期，首尾包含、重叠归前段；真实行程日期不改。明确手改津贴含0及清空保留，自动建议不因保存变成人工覆盖。

**正式付款：** 只填本次支付，不把合同总额或历史已付相加。统一主表 `currency`，不增加各行原币种。收款使用本次外部收款人，不套员工花名册；合同、用印和费用关联保留原规则。

**餐费交通：** 时间组件精确到分钟，默认加班当天18:30；日期含糊先问，明确时间或清空保留，不猜前一天或用申请日替代。餐补按原公式只读，交通可改。打卡证明和报销票据分栏；明细只显示公司／币种、真实字段、合计及短提示，不给员工材料台账或长篇来源说明。

**体检：** 固定CNY、原金额可改，超过1500元沿原代码封顶。公司沿原合同默认和“有银行账号”目录，原可空字段不强填。完整申请显示花名册默认或明确修改的收款五项及附件名。不造项目、科目、汇率或材料台账；正式员工与一年一次仍由原表校验。

## 保留原确认次数

费用、出差、正式付款和餐费交通：展示明细→修改并确认明细→补主表→展示完整申请→新确认→提交。第一轮用当前 `reviewSha256` 执行 `confirm-details`；最终 `preview` 展示后停止，等待新确认，再用当前 `draftSha256`提交一次。

体检、银行卡和Demo仍只有一次完整确认。保存、回读、应用、摘要或最初办理意图都不能代替确认；未变化的已确认明细不重问，有变化只核对受影响内容。页面不提供直接提交接口。

## 银行卡变更直接对话核对

不调用 `editor`、`read-edit` 或 `apply-edit`。文字或自愿照片提取账号、户名、银行、城市、支行，前台可合组，不漏原生五项、不猜缺失。照片不上传原表。`prepare`后对话核对，修改仍同草稿，`preview`后一次新确认提交。旧文件不导入，原草稿保留。

变更提交后，仍会使用的旧卡经本人同意才存personal昵称、尾号、用途，不存完整资料；以后明确换回才从本人已完成且同意的历史核对，缺记录自行提供，见[PERSONAL](PERSONAL.md)。

## 尚未迁移的 HTML 入口

3.4.0付款Demo也接本机保存与MD兜底，仍有醒目Demo标识、独立供应商字段和一次完整确认，不套正式付款字段。旧版导出文件仅属历史，本版不要求员工导出交回。

本机文件含申请资料，只保存在当前草稿目录，不进入公开仓库或长期personal。Node保存不是公司服务端业务鉴权，平台权限和审核仍沿既有规则。
